# Projeto Biblioteca PHP (PDO com MySQL e PostgreSQL)

Este é um projeto prático feito para entender como conectar uma aplicação PHP Orientada a Objetos em diferentes bancos de dados (MySQL e PostgreSQL) usando PDO, separando as responsabilidades com o padrão Repository.

## Como rodar o projeto

1. **Bancos de Dados:**
   - Crie um banco chamado `biblioteca2` no seu MySQL e rode o script `database/mysql.sql`.
   - Crie um banco chamado `biblioteca2` no seu PostgreSQL e rode o script `database/postgresql.sql`.

2. **Configuração:**
   - Se os seus usuários ou senhas forem diferentes, ajuste as variáveis de ambiente ou altere direto no arquivo `config/Database.php`.

3. **Testando:**
   - Jogue a pasta do projeto no seu servidor local (Laragon, XAMPP, etc).
   - Acesse pelo navegador: `http://localhost/biblioteca-php/public/` (ou o domínio do Laragon, se estiver usando).

## Anotações do Exercício

### Diferenças na prática (MySQL vs PostgreSQL)
Durante os testes (Exercício 09), deu pra notar que a estrutura do código PHP quase não muda, mas o banco por baixo é diferente:
- **Portas e Drivers:** O MySQL usa a porta 3306 e o driver `mysql:`. O Postgres usa a porta 5432 e o driver `pgsql:`.
- **IDs automáticos:** No MySQL a gente usa o famoso `AUTO_INCREMENT`. No Postgres, a sintaxe atual recomendada é `GENERATED BY DEFAULT AS IDENTITY`.
- A vantagem é que usando SQL padrão nos `SELECTs` e `INSERTs`, o PDO roda de boa nos dois.

### Por que PDO + Repository não formam um ORM? (Exercício 10)
Basicamente, o PDO só abre a porta para conversar com o banco e mandar comandos SQL. O Repository é só um jeito de organizar esses comandos em um lugar só pra não bagunçar o código. 

Eles não são um ORM porque não fazem o trabalho mágico de transformar uma tabela em um objeto sozinho. A gente ainda tem que escrever o `SELECT` na mão, pegar o array que o banco devolve e montar o `new Livro(...)` linha por linha. Um ORM de verdade (tipo o Eloquent ou Doctrine) faria isso tudo sozinho.

## 8 Conceitos que aprendi
1. **PDO:** É a classe nativa do PHP que faz o meio de campo entre o código e vários tipos de banco de dados.
2. **Driver:** É a "tradução". O PDO precisa do `pdo_mysql` pra saber falar com o MySQL e do `pdo_pgsql` pra falar com o Postgres.
3. **DSN:** É a string que tem o endereço do banco (tipo, host, porta e nome do banco) pra gente conseguir conectar.
4. **Prepared Statement:** É um jeito seguro de mandar variáveis pro banco. Em vez de juntar a string do SQL com a variável do usuário, a gente usa `prepare()` pra evitar ataques (SQL Injection).
5. **Model (Livro):** É a classe que representa o dado em si, sem se importar com como ele vai ser salvo no banco.
6. **Repository:** A classe que cuida exclusivamente de salvar e buscar as coisas no banco. 
7. **Injeção de Dependência:** Em vez do Repository criar a conexão com o banco lá dentro dele, a gente passa a conexão pronta pelo construtor. Fica bem mais fácil de testar.
8. **ORM:** Uma ferramenta robusta que mapeia classes e tabelas automaticamente.

## Respostas da Revisão

* **PDO é ORM? Qual é a função do driver?**
Não é. O PDO é só uma API pra acessar os dados. O driver é o que ensina o PDO a falar o idioma específico daquele SGBD.

* **Repository dispensa SQL? Por que usar `prepare()`?**
Não dispensa, a gente ainda escreve o SQL dentro do Repository. A gente usa o `prepare()` pra separar o código SQL do valor que o usuário digitou, garantindo a segurança do banco.

* **ORM elimina diferenças entre MySQL e PostgreSQL?**
Ajuda muito na sintaxe básica, mas não resolve tudo. Cada banco tem recursos únicos (como tipos de dados e otimizações) que o ORM não consegue padronizar 100%.
